# ICU 77 root collation data, schema 1

`root-icu77.bin` contains ICU4C 77.1 root collation tables for the development
prototype. It is generated by `../export/export-root.cpp` from the unmodified,
full-data ICU release. It contains character mappings and context tables, never
sort keys for known test strings. The Rust executable loads this file without
linking to ICU or executing the exporter.

All integer fields are unsigned, little endian, tightly packed, and unaligned.
There is no padding. Counts are `u32`. The file ends immediately after the last
context entry; readers must reject truncation or trailing data. Code-point
ranges cover every value from zero through `0x10ffff`, including surrogates.

## Header

| Field | Representation | Value / meaning |
| --- | --- | --- |
| Magic | 8 bytes | ASCII `BRSPRI77` |
| Schema | `u32` | `1` |
| ICU version | two `u32` | `77`, `1` |
| Unicode version | two `u32` | `16`, `0` |
| CLDR version | two `u32` | `47`, `0` |
| Primary options | `u32` | Root `CollationSettings::options` with PRIMARY strength |
| Variable top | `u32` | Root `CollationSettings::variableTop` |
| Numeric primary | `u32` | Root `CollationData::numericPrimary` |

The effective public attributes and runtime data version are also recorded in
`root-icu77.json`. The exporter checks the versions and the attributes required
by this prototype, and fails on an unexpected root configuration.

## Sections, in order

Every section starts with its element count. Counts describe elements, not
bytes.

| Section | Element layout | Source |
| --- | --- | --- |
| CE32 ranges | `end_inclusive: u32`, `ce32: u32` | `CollationData::getCE32` over the whole code-point domain |
| CE32 table | `u32` | All `ce32s` |
| CE table | `u64` | All 64-bit `ces`, including offset data |
| Raw contexts | `u16` | All `contexts` UTF-16 units |
| Jamo | `u32` | All 67 `jamoCE32s` entries, preserving original tags |
| Compressible bytes | `u8` | All 256 `compressibleBytes` flags |
| FCD16 ranges | `end_inclusive: u32`, `fcd16: u16` | `Normalizer2Impl::getFCD16` over the whole domain |
| Decoded contexts | variable | See below |

A range begins immediately after the preceding end; the first begins at zero.
Adjacent equal-valued ranges are merged. The original mapping values are
unchanged: this is an index representation change, not ICU4X collation data
reduction or runtime normalization. The full CE and CE32 tables preserve
canonical closure mappings present in the ICU root data.

Each decoded context has:

1. `context_index: u32`, the offset into the raw contexts table used by the
   original CE32.
2. `default_ce32: u32`, reconstructed from the first two raw UTF-16 units exactly
   as `CollationData::readCE32` does.
3. `entry_count: u32`.
4. For each entry: `utf16_length: u32`, that many `u16` units, and `ce32: u32`.

Contexts are ordered by ascending index; entries retain ICU's `UCharsTrie`
iterator order. Context keys are the original trie keys. Contraction keys are
forward sequences; prefix keys are encoded in reverse code-point order as ICU
expects when walking backward. Supplementary characters remain UTF-16 pairs;
this is not reversal of individual UTF-16 units. The referencing CE32 retains
the prefix/contraction tag and all flags. Context entries can themselves refer
to a context, and those referenced contexts are exported recursively.

FCD16 stores the leading canonical combining class in its high byte and the
trailing class in its low byte. These values support ICU's discontiguous
contraction algorithm. The input is not uniformly decomposed or reordered.

## Data and algorithm provenance

The source release, archive checksum, relevant source checksums, generated
binary checksum, and table counts are recorded by `../export/generate.py` in
`root-icu77.json`. Algorithm and data use is covered by the included
`LICENSE-ICU.txt`; see `NOTICE.md` for upstream file identities and the changes
made for this prototype. Regeneration requires ICU only in the development
environment. Running the Rust prototype requires only the checked-in data.

## Independent IDENTICAL NFD data, schema 1

`root-icu77-nfd.bin` is a separate file; adding IDENTICAL does not change the
PRIMARY/CE blob above. All integers below are little-endian and tightly packed.

| Field | Encoding |
| --- | --- |
| Magic | Eight ASCII bytes `BRSNFD77` |
| Schema | `u32`, value 1 |
| ICU / Unicode / CLDR versions | Six `u32`: `77,1,16,0,47,0` |
| Canonical mapping count | `u32` |
| Each mapping, sorted by scalar | `code_point:u32`, `length:u32`, then `length` scalar `u32` values |
| Combining-class range count | `u32` |
| Each range | `end_inclusive:u32`, `canonical_combining_class:u8` |

Mappings are fully recursive canonical decompositions from ICU77
`Normalizer2::getNFDInstance()->getDecomposition`, including all Hangul syllables.
An unlisted code point maps to itself. CCC ranges partition the complete
U+0000..U+10FFFF domain, including zero-CCC and surrogate ranges. There is no
padding or trailing data. The exporter does not read sort keys or test strings.

The recorded file is 255,286 bytes and contains 13,253 mappings (36,567 scalar
values, maximum mapping length 4) and 590 CCC ranges. Its SHA256 is
`45c59eca6b851ea843c8088343742f1ac706ca4bb657c807a981e1c708a337de`.
Source identities and generation settings are in `root-icu77-nfd.json`.
These mappings are used only for the final IDENTICAL NFD/BOCSU level; the CE
iterator continues to consume the original, normalization-OFF root input.
