## Outcome and reason

Streaming consumers can already have observed output or matches when a budget or sink fails.

## Starting state

Only initial byte iterator/replacement operations exist; error-once and written-prefix semantics are not accepted.

Published source baseline: `1b0149efb649bcec7b5d6c4c0be2f7e403189cea`. Paused implementation sources are preserved separately in the [checkpoint](https://github.com/1298345095/BoostRegexRS/blob/work/root-primary-cloud/docs/development/tickets/checkpoint/README.md). Restore them in an isolated checkout when resuming; an archive is not validation evidence.

## Deliverable

- Apply limits and sink errors to write-to, callback and iterator APIs using a terminal error state.
- Preserve previously returned items and already written output, and keep internal results independent between invocations.

## Acceptance

- [ ] An iterator returns every previously delivered match, exactly one error at exhaustion, then permanent end including repeated next calls.
- [ ] An external sink retains precisely its written prefix when an error is reported; no rollback is promised.
- [ ] One-shot, iterator and streaming tests exercise the same failure points and demonstrate their deliberately different result-delivery contracts.
