# [U09] Apply arbitrary collation keyword settings and script-name reordering

Part of #2. Implementation is paused at the user's request; this ticket records remaining work.

**Ticket:** `U09` · **Workstream:** Fixed Unicode and ICU locale behavior

**Blocked by:** [#44](https://github.com/1298345095/BoostRegexRS/issues/44), [#12](https://github.com/1298345095/BoostRegexRS/issues/12)

## Outcome and reason

New valid keyword combinations compute effective settings and complete keys on demand; invalid requests fail in the same category.

## Starting state

Implementation: Numeric/FCD/case/shift/backward-secondary/max-variable/reorder setters exist for explicit settings. Text keyword overlay parsing does not. Evidence: The 384 finite attribute profiles and script aliases are exported references, not runtime keyword handlers. Missing: Exact coll.cpp keyword order, value parsing, unsupported/invalid behavior and text-to-script conversion.

Published source baseline: `1b0149efb649bcec7b5d6c4c0be2f7e403189cea`. Paused implementation sources are preserved separately in the [checkpoint](https://github.com/1298345095/BoostRegexRS/blob/work/root-primary-cloud/docs/development/tickets/checkpoint/README.md). Restore them in an isolated checkout when resuming; an archive is not validation evidence.

## Deliverable

- Entry point: A parsed legacy keyword set plus resolved tailoring defaults to the two Boost key strengths
- Implement source-recognized keywords, value domains, case treatment, capacity limits, unknown-key ignoring and deprecated unsupported keys.
- Implement colReorder token length before ICU loose alias matching, special groups, default/others handling and kv limits using BRSSAL77 and ScriptGroups77.
- Apply overlays in the actual source order, then force the two Boost collators to PRIMARY and IDENTICAL as icu.hpp does.

Data upgrades are explicit; a toolchain update must not change character behavior. The standalone library's default configuration must provide the full promised capability set, including Unicode, wide input and locale support. Read the relevant pinned implementation sources and derive the complete mechanisms and invariants before changing code. Keep the runtime on stable Rust with only the OS API boundary allowed by ADR-0002 and no C/C++ or ICU library backend. Preserve original input-unit positions and all captures. Do not use input-specific answer tables, blanket input prenormalization, skipped inputs, weakened gates or unapproved compatibility exceptions. Source-defined FCD and IDENTICAL normalization remain part of their respective mechanisms.

Update the capability matrix with exact evidence, not ticket closure alone. Do not close the parent, merge main, release, or integrate librime-rs.
