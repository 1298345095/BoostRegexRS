## Acceptance

- [ ] Comparison includes compile status and group count, indexed/named groups, matched/unmatched distinction, all original-unit ranges, histories, prefix/suffix, partial state, iteration order, replacement bytes and error category/position where the operation exposes them.
- [ ] Collation compares every raw ICU byte and every Boost u32 element, including terminal handling, long keys, NUL and ADR-0005 true-empty identity.
- [ ] Missing, duplicate, reordered-without-ID-mapping, truncated, malformed or extra rows, wrong input hashes and changed binary/data identities fail the run; totals reconcile independently.
- [ ] Semantic pass, semantic difference, approved exception, expected rejection, reference error/resource outcome and not-covered are separate statuses. A timeout/crash is never an empty match or ordinary pass.
- [ ] The comparator has bounded fixtures with deliberately changed fields and framing failures that it demonstrably rejects; candidate output is never used to generate its expected answers.
- [ ] Every run records the exact reference configuration, candidate commit/tree/dirty state, binary/data hashes and raw commands.

## Size and completion rule

One fresh context: use the accepted implementation and reusable harness for this named family, target, measurement pack or audit. A newly discovered implementation mechanism or substantial optimization becomes a bounded blocking ticket; keep this gate open until its linked fix passes. Evidence closes only this ticket and its explicitly mapped capability obligations; implementation fixes remain in the responsible capability tickets.

The reference contract is Boost.Regex **1.89.0**, ICU4C **77.1**, Unicode **16.0.0** and CLDR **47**, with complete unfiltered ICU data. Data upgrades are explicit; a toolchain update must not change character behavior. The standalone library's default configuration must provide the full promised capability set, including Unicode, wide input and locale support. A reduced configuration must be explicit and separately documented and verified.

Read the relevant pinned implementation sources and derive the complete mechanisms and invariants before changing code. Keep the runtime on stable Rust with only the OS API boundary allowed by ADR-0002 and no C/C++ or ICU library backend. Preserve original input-unit positions and all captures. Source-defined FCD and IDENTICAL normalization remain part of their respective mechanisms.

Record passes, differences, approved exceptions, expected rejections, reference errors and uncovered work separately; preserve failed runs. Finite passing cases do not prove arbitrary-input correctness. Update the public API documentation and execute the relevant examples for every implemented or changed public behavior.

Update the capability matrix with exact evidence, not ticket closure alone. Do not close the parent, merge main, release, or integrate librime-rs.
