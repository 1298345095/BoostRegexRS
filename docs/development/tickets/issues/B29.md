# [B29] Add source-compatible byte token iteration

## Outcome and reason

Callers can iterate selected capture groups and unmatched byte spans in the requested source-defined order.

## Starting state

Present: Match iteration and capture ranges exist as prerequisites. Remaining: No token iterator API or token-selection state machine exists. Evidence caveat: Implementation presence and selected pre-pause local tests do not establish independent compatibility. The 35-test raw output was not archived; see the top-level checkpoint.

Published source baseline: `1b0149efb649bcec7b5d6c4c0be2f7e403189cea`. ## Deliverable

- Add a typed native selection API for one/multiple groups and unmatched spans.
- Implement source ordering, duplicate selections, unmatched capture results and the first-selector rules for initial/trailing unmatched output.
- Use original byte ranges and the token iterator's own source continuation behavior.
