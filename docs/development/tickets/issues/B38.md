# [B38] Add streaming byte format and replacement output

## Outcome and reason

Callers can format or replace into an output target and receive explicit writer/engine errors while retaining bytes already written.

## Starting state

Present: Formatting and replacement currently build owned Vec<u8> values. Remaining: No caller-provided byte output target API or writer error contract exists. Evidence caveat: Implementation presence and selected pre-pause local tests do not establish independent compatibility. The 35-test raw output was not archived; see the top-level checkpoint.

Published source baseline: `1b0149efb649bcec7b5d6c4c0be2f7e403189cea`. Paused implementation sources are preserved separately in the [checkpoint](https://github.com/1298345095/BoostRegexRS/blob/work/root-primary-cloud/docs/development/tickets/checkpoint/README.md). Restore them in an isolated checkout when resuming; an archive is not validation evidence.

## Deliverable

- Add one byte sink boundary shared by owned collection and caller-provided streaming, using a native safe output interface.
- Wire format-string and callback replacement through the boundary without buffering the full result.
- Preserve emitted bytes on writer or engine error; keep the owned API's all-or-error contract distinct.
