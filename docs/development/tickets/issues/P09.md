## Size and completion rule

One fresh context: only this named connection, source acquisition, target reference setup or package/API seam and its bounded end-to-end verification.

The reference contract is Boost.Regex **1.89.0**, ICU4C **77.1**, Unicode **16.0.0** and CLDR **47**, with complete unfiltered ICU data. Data upgrades are explicit; a toolchain update must not change character behavior. The standalone library's default configuration must provide the full promised capability set, including Unicode, wide input and locale support. A reduced configuration must be explicit and separately documented and verified.

Read the relevant pinned implementation sources and derive the complete mechanisms and invariants before changing code. Keep the runtime on stable Rust with only the OS API boundary allowed by ADR-0002 and no C/C++ or ICU library backend. Preserve original input-unit positions and all captures. Do not use input-specific answer tables, blanket input prenormalization, skipped inputs, weakened gates or unapproved compatibility exceptions. Source-defined FCD and IDENTICAL normalization remain part of their respective mechanisms.

Run real, independent tests for the implemented behavior and retain reproducible commands, full results, exit statuses and source/binary/data/tool identities. Record passes, differences, approved exceptions, expected rejections, reference errors and uncovered work separately; preserve failed runs. Finite passing cases do not prove arbitrary-input correctness. Update the public API documentation and execute the relevant examples for every implemented or changed public behavior.

Retain source/data licenses and publish authored tools and durable evidence outside target. When implementation resumes, use scoped, verified English commits on an independent branch. Update the capability matrix with exact evidence, not ticket closure alone. Do not close the parent, merge main, release, or integrate librime-rs. If a source/contract conflict requires a new decision, report it without silently changing the contract.

Implementation and implementation-test execution remain paused until the user resumes them. Ticket publication, readiness labels and dependency completion do not resume development.
