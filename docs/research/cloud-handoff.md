## 阶段开始时的状态（历史起点）

根 Rust crate 仍是初始化骨架。已有内容是设计决定、独立研究探针和实测证据；没有完整正则引擎或 Rust 排序键实现。当前推进不需要重新开展广泛需求访谈；通常的实现选择由执行者处理，只有确实需要改变已确认契约时再提出具体问题。

本机实测基准为官方 Boost.Regex 1.89.0 + ICU4C 77.1 / Unicode 16.0.0 / CLDR 47。ICU4X 2.0 的字符映射 / 分类加适配在九字段全码点对照中一致，但其默认排序路径在补充非 FCD 语料中有 145 对差异。完整排序需要对齐 ICU77 数据、迭代和键编码，不能只给 ICU4X compare 增加一个输出接口。

Q28 / Q29 已接受并写入 ADR-0005：`getloc` 保留默认 locale 查询行为；空串返回有效键，异常作为明确兼容例外。10 个测试 locale 的例外参考键为 PRIMARY `[0]`、IDENTICAL `[1,1,1,1]`。原始失败记录和例外期望值分别保存。

## 云端缺少的本机内容

- `target/` 按设计忽略，编译缓存、下载包、DLL / EXE / PDB 及 42.5 MiB 的 `codepoints.bin` 没有上传。需要时由固定版本参考程序重新生成。
- 可审阅的小型证据已经在 `docs/research/assets/`：原始完整排序键、候选比较符号、反例、摘要、版本和哈希。摘要不能替代完整输入数据重新测试。
- 报告或 manifest 中的 `D:/...`、`C:/...` 是历史来源定位，不是云端依赖路径。`librime-rs` 及其 Boost 缓存不在仓库中；本轮原型无需该消费者仓库。
- 本地 PowerShell / MSVC 运行脚本和 `probe.cpp` 的 Windows SEH 不能直接视为 Linux 工具。先确认实际云端 OS，再添加适用的构建与运行入口，保留 Windows 支持。若需要隔离原版崩溃用例，用子进程记录结果；不要让一个参考崩溃中断全部采样，也不要将其改写为成功。
- 从官方发行源取得固定 Boost 1.89.0 与 ICU77.1 源码，核对官方摘要并保存实际编译 / 数据身份。仅匹配版本号的任意系统 ICU 不足以证明参考数据一致。网络不可用时先使用已提交语料和快照完成独立工作，说明缺少的具体源码或依赖；不默默换版本。
- `snapshot-manifest.json` 记录的是对应历史采样时的文件摘要。工具后续修改可能使当前源码摘要不同；它不是“所有当前文件必须等于旧版本”的规则。保留历史证据，新运行写入独立目录和新 manifest。

## 首轮云端任务边界

完成“可复现参考环境 + root locale 的纯 Rust PRIMARY 完整排序键原型”。这是一项独立可验收的工程阶段；首版整库完整兼容的最终门槛不变，IDENTICAL、多 locale、完整正则引擎和 `librime-rs` 接入不属于本轮完成声明。

先使参考程序和现有候选在云端实际环境可运行，确认版本并重放已提交语料，将结果与历史 Windows 证据分别记录。随后按完整排序键实现路线，建立固定 ICU77 数据导出 / 生成链和 Rust 数据表示，实现 root PRIMARY 所需的排序元素迭代、压缩及 Boost 键包装。C++ / ICU 可以用于开发期参考和数据生成；运行被测 Rust 实现时不链接或调用这些参考库。保留导入算法 / 数据的许可及来源。

使用 Rust stable 并保存实际工具链版本。将实验工具与根库公开 API 隔离；固定被测字符数据。原型按输入实际计算键，不能通过查已知输入的参考输出表实现。暂未支持的输入须明确报出，不能算通过；当前已确认的合法输入语义不因原型实现方便而改变。

## 本轮完成条件

1. 提供从干净 checkout 准备依赖、生成固定数据、构建和运行对照的可重复命令，依赖放在项目局部目录。
2. root PRIMARY 覆盖现有两组语料，以及 ASCII、重音 / 组合符号、Han、Hangul、补充平面、空串、内嵌 NUL、忽略字符、压缩与长键边界。增加固定种子的生成语料；逐元素比较 Boost 暴露的完整 u32 键，排序符号一致仅作为附加检查。
3. 区分原版参考结果、已批准例外、Rust 差异和未覆盖项。已知 145 对差异属于 IDENTICAL 的后续回归目标，不能宣称 PRIMARY 阶段修复了它们。
4. 输出实现代码、必要的测试、可复现数据来源和结果报告，说明实际覆盖与剩余能力。执行相关构建、测试和格式 / lint 检查，报告真实结果。六平台、全引擎性能与内存门槛仍属于后续完整验收。

遇到实现缺口应继续定位最小反例并修复；确有外部阻塞时保留已完成的可运行成果，明确阻塞与下一步。最终交付包括改动摘要、复现命令、通过 / 失败 / 未覆盖数量及下一阶段建议，不能仅交付计划或把尚未验证的能力写成通过。
