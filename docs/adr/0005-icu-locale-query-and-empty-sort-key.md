# 保留 ICU locale 查询行为，并定义空串排序键例外

用户已确认 Q28 / Q29。Boost.Regex 1.89.0 的 ICU 字符规则在 `imbue` 后使用指定 locale 排序，但 `getloc()` 返回默认 locale；Rust 等价接口保留这一可观察行为，不将查询值改为最近设置的值。默认值根据约定运行环境取得，不能把本次实测的 `en_US` 写死；`imbue` 返回实际先前 locale 的行为也保持一致。

本机原版 Boost + ICU 77.1 的空串 IDENTICAL 排序路径会把 null / 长度零传给 ICU 并发生访问异常。Rust 对空串返回确定、有效的排序键，作为已经批准的兼容例外；不会为复现此异常而使进程崩溃，也不改成受控错误。例外的期望值由固定 ICU 77.1 对有效地址 / 长度零的参考调用产生，再应用 Boost 的返回序列约定：每字节转为一个 u32，长度大于一时移除尾部终止零，单个零保留。PRIMARY 的正常空串结果继续兼容。

例外参考与原版参考分别保存：原版访问异常仍是访问异常，不能改写历史结果为通过。未来 Rust 测试分别报告原版兼容结果与已批准例外的验收结果。此决定仅覆盖该空串排序边界，不自动豁免其它上游差异，也不表示完整排序键已实现或验收完成。证据见 [ICU 探针实测](../research/icu-probe-results.md)。
